# 公司-线上小活动

> 同事之間可以直接開房間一起玩的線上團康遊戲。開房、給密碼、大家進來連線對戰，即時同步。
> 內建六種遊戲：**賓果**、**終極密碼**、**21點**、**牛牛**、**比大小**、**杯子抽獎**，
> 可以排成賽程一路玩下去。

線上遊玩：<https://hengda188188-png.github.io/company-events/>

---

## 這個工具是做什麼的

團隊活動、尾牙、聚餐想玩遊戲，傳統做法是印紙卡、有人負責喊號、還要有人盯著誰先連線。
人一多就亂，喊到哪一號了也常常有人沒聽到。

這個工具把整套搬到線上：**一個人開房間，其他人用網址進來，狀態即時同步，系統自動判定輸贏。**
不用安裝 App，手機、電腦打開瀏覽器就能玩。

## 怎麼玩

1. 打開網址，先取一個暱稱（只存在自己這台電腦）
2. **開房的人**：填房間名稱 → **排賽程**（要玩哪些遊戲、順序、各幾局）→ 按「建立房間」（想限制人進來就設個房間密碼，可留空）
3. **其他人**：在首頁的房間列表點進去 —— 列表會直接顯示這間房要玩什麼、共幾局
4. 依當前遊戲開始（賓果／終極密碼要先「鎖定」等大家準備；抽獎由房主直接「打亂並開始」）
5. 一局打完，房主按左上按鈕推進到下一局／下一個遊戲

## 🗓️ 賽程

建房時先選 **單一遊戲** 或 **多遊戲賽程**：

- **單一遊戲**：挑一個遊戲，設定要玩幾局
- **多遊戲賽程**：把想玩的遊戲加進清單，用 ↑↓ 排順序、各自設定局數（最多 8 個遊戲，每個最多 20 局）

例如排成 `🎟️賓果×2 → 🔢終極密碼×1 → 🥤抽獎×2`，房間就會照這個順序跑完 5 局。

**房裡每個人的左上角都有賽程面板**，看得到完整清單、目前玩到哪一個遊戲、進行到第幾局（`第 3 / 5 局`），
已完成的階段會變淡、進行中的會反白。

房主可在「尚未開始」的狀態按 **「✏️ 編輯賽程」** 調整。
**比賽一旦開打，已結束與進行中的階段就鎖住不能改**（會標示「已結束」／「進行中」），
只能調整後面還沒玩的順序、局數與積分 —— 進度與累積的積分完全不受影響。
還沒開打時整份賽程都能自由調整。
**只要賽程有變動（改遊戲、改順序、改局數）或推進到下一局，房裡所有人都會跳出提示，日誌也會留下紀錄**，
不會有人搞不清楚現在要玩什麼。

## 六種遊戲

### 🎟️ 賓果
輪流叫號，連成指定條數就贏。公共號碼範圍 1–50。

| 設定 | 說明 |
|---|---|
| **幾條算 BINGO** | 房主自訂連成幾條才算贏 |
| **同時 BINGO 模式** | 可選「先搶先贏」或「系統自動判定」 |
| **刷新我的號碼** | 開局前可以重抽自己的號碼卡 |
| **炫耀** | 隨時分享目前條數（同條數最多三次） |

### 🔢 終極密碼
系統藏一個數字，依順位輪流猜，猜完範圍就往內縮。

| 設定 | 說明 |
|---|---|
| **數字範圍** | 房主自訂，例如 1～100 |
| **猜中的人** | **獲勝・密碼專家**（猜中的人拿走該局積分）或 **受罰**（傳統玩法，不計分） |

兩種模式的最佳策略剛好相反：受罰模式用二分法把範圍砍半、把風險丟給下家（約 7 次結束）；
密碼專家模式則是猜邊緣拖時間，等於線性掃描（100 的範圍平均 50 次命中）。
**人多的場子建議用密碼專家模式** —— 受罰模式七次就結束，十幾個人時大部分人連一次都輪不到。

密碼在**所有人準備完成、正式開局的那一刻**才產生並寫入資料庫，開局前資料庫裡沒有答案可偷看。

### 🃏 21點
**只有第一張是明牌**，其餘蓋著，別人看不到你的點數。輪到你就一路要牌，直到停牌或爆牌才換下一家。
最接近 21 點又沒爆的人獲勝；全員爆牌時由最接近 21 點的人獲勝。開牌時才全部翻開。
A 自動算 1 或 11，J/Q/K 算 10。房主可設定起手發幾張（1–3，預設 2）與用幾副牌（1–4）。

### 🐮 牛牛
每人 **3 張暗牌**（只有自己看得到），再從**桌面公共牌挑 2 張**湊成 5 張。
**桌面牌是共用的**，不會被拿走 —— A 用了那兩張，B 也能用同樣的兩張。

任 3 張湊成 10 的倍數就「成牛」，剩下 2 張的個位數就是牛幾（0 算牛牛）。

| 設定 | 說明 |
|---|---|
| **桌面公共牌張數** | 3～8 張，預設 5 |
| **怎麼配牌** | 系統自動配最佳組合 ／ 玩家自己挑（挑錯就判無牛） |

> 挑哪兩張差很多：實測桌面 5 張時，最好與最差的挑法平均差 **7.87 牛**，
> 而「怎麼挑都無牛」只有 2.2%。所以自己挑是真的考驗眼力。
> 手動模式按「開牌」前會先跳確認，列出你的組合與結果，避免手滑點到就定案。

### ⚔️ 比大小
每人抽指定張數的暗牌（1–5，預設 1），比總點數。A=1、J=11、Q=12、K=13。各自開牌後結算。

### 🎴 牌組數與同分加賽

三種牌局都可以在左側設定 **用幾副牌（1–4 副）**。多副牌隨機性更高，人多時也才夠發
（例如 11 人玩牛牛需要 55 張，用 2 副就夠）。

> **三種牌局每一局都會決出唯一勝者。**
> 同分時**重新洗一副全新的牌，只讓同分的人再比一次**，其餘玩家本局出局；
> 若又同分就再加賽一輪，直到分出勝負。畫面與日誌會標明「⚔️ 同分加賽第 N 輪」與還在場的人。
>
> 這個做法也順便解決了多副牌的副作用 —— 用兩副牌時同一張牌面可能同時出現在兩個人手上
> （實測 4 人各抽 1 張有 5.94% 的機率發生），此時「比最大單張」已經分不出高下，但加賽可以。
>
> 賓果的「系統自動判定」模式若多人同時達標，同樣會**重新發號碼卡**只讓他們再比一次。

### 🥤 抽獎（杯子蓋獎品）
房主設定杯子數量與獎項，獎品被打亂蓋在杯子下，玩家各挑一個。

| 設定 | 說明 |
|---|---|
| **杯子數量** | **上限 = 參加人數**（保證每杯都有人掀，獎不會留在桌上） |
| **獎項設定** | 按「＋ 新增獎項」逐筆加，每筆可填 **名稱／積分／數量**，例如「二獎 5分 × 2個」 |
| **誰可以掀杯子** | 依順位輪流 ／ 自由搶 |
| **每人可掀幾個** | 預設 1 個，0 代表不限 |

獎項比杯子少時，其餘杯子自動補「銘謝惠顧」（0 分）。

**選走的杯子會鎖定變灰，只看得到是誰選的，內容一律保密**；等杯子全被選走（或每個人都選滿了），才會一次翻牌開獎。
沒被選走的杯子在開獎後維持蓋著，並列出「沒開出去的獎項」。

> 杯子與獎項的對應**不會預先寫進資料庫**。玩家掀開杯子的當下，才從「還沒開出去的獎項池」裡隨機抽一個給他。
> 機率跟事先洗好牌完全一樣（已用模擬驗證各杯中獎率均勻、開出的獎項總和恰好等於清單），
> 所以**開局前沒有任何人（包含房主）能預先知道哪一杯有獎**。
>
> ⚠️ 但要誠實說明：杯子一旦被掀開，獎項就明文寫進資料庫，畫面上的「保密到開獎」只是 UI 遮蔽。
> 終極密碼的答案也一樣會存在所有人的瀏覽器裡。純前端 + Firebase 的架構沒辦法真正隱藏已寫入的資料，
> 想偷看的人開 DevTools 就看得到 —— 這是架構限制，不是設定問題。

## 🏅 積分與排名

賽程裡每個遊戲都能各自設定「贏一局拿幾分」（設 0 = 不計分）。

> **每一局只有唯一勝者拿走該局的全部積分。**
> 因此整場比賽發出的積分總額 = `Σ(局數 × 積分)`，事先就算得出來 —— 要拿積分換獎品或獎金時，預算完全可控。
> 已用模擬驗證：3 萬份賽程跑完，每一份發出的總額都分毫不差。

同分一律靠加賽解決，不會出現並列：**牌局重新洗牌、賓果重新發號碼卡**，只讓同分的人再比一次。

抽獎的積分在左欄的「獎項設定」裡逐筆指定，每一筆有**名稱／積分／數量**三欄：

| 獎項名稱 | 積分 | 數量 |
|---|---|---|
| 頭獎 禮券1000 | 10 | 1 |
| 二獎 飲料券 | 5 | 2 |
| 參加獎 | 0 | 3 |

按「＋ 新增獎項」加一筆，下方會即時顯示「共幾個獎、總積分多少、需要幾個杯子」。
抽獎不吃賽程階段的積分設定（賽程面板會標成「獎項帶分」），因為它是**每個人抽到什麼就拿多少分**，
一局裡可以有好幾個人同時得分，跟其他遊戲「唯一勝者拿走全部」的模型不一樣。

> 抽獎的杯子數上限就是參加人數，所以每個杯子一定有人掀，**獎金一定發得完**。
> 已用模擬驗證：6／8／12／20 人的場子各跑 3 萬局，每一局發出的積分都剛好等於獎項總額。
> 獎項數量若超過人數，程式會在開始前擋下並要求減少。

**積分榜**在左欄常駐顯示前三名，點開是完整排名，再點任一位玩家可以展開他**在各個遊戲分別拿了多少分**。

賽程跑完、房主選擇從頭再來時會**詢問**要不要順便把積分歸零 —— 選擇保留就能繼續累積下一圈
（單一遊戲的房間每打完一局就算跑完一輪，所以這個詢問很重要，否則分數會被清掉）。
房主也可以隨時在積分榜手動歸零。

## 👀 觀戰模式

同分加賽時只有平手的人會繼續比，其他人這一局就沒事做了。
這些人畫面上會出現 **「☕ 你這一局已經出局，先休息一下」**，並自動切換成觀戰：

- 看得到決戰過程、誰還在場、日誌與積分榜照常更新
- 操作區會變淡且無法點擊，賓果的舊號碼卡會收起來（避免誤以為還能玩）
- 下一局開始時自動回到牌桌

遊戲開始後才進房的人同樣會進觀戰模式，房主開下一局時會自動排進順位。

## 共用功能

| 功能 | 說明 |
|---|---|
| **即時連線** | 所有人的狀態、日誌、玩家清單即時同步，不用重新整理 |
| **賽程面板** | 房裡所有人都看得到要玩哪些遊戲、順序、局數與目前進度 |
| **變更通知** | 房主一改賽程或推進局數，所有人立刻跳提示 + 寫進日誌 |
| **房間密碼** | 建房時可設密碼，避免不相干的人進來（密碼經雜湊後才送出） |
| **玩家排序與鎖定** | 房主可調整玩家順序並鎖定 |
| **🎲 隨機排序** | 一鍵把所有玩家的順位重新洗牌，所有遊戲都能用 |
| **移交房主** | 房主要離開時可以把權限交給別人，遊戲不會中斷 |
| **先手每局輪替** | 每開一局，第一個動作的人往後輪一位，避免同一人長期佔位置優勢 |
| **每局重新洗牌** | 牌局每一局（含每輪加賽）都重洗成完整牌堆，不延用上一局的殘牌 |
| **同分加賽** | 牌局重洗、賓果重發號碼卡，只讓同分者再比一次，直到決出唯一勝者 |
| **🏅 積分榜** | 每局積分可自訂，總額可預算；可展開查看每人在各遊戲的得分 |
| **跳過離線玩家** | 有人斷線不會卡住整局 |
| **遊戲日誌** | 誰做了什麼都有紀錄，抽獎結果也會完整列在日誌裡 |
| **內建操作說明** | 畫面上的「❓ 操作說明」有完整教學，不用另外看文件 |

## 技術

- 前端：單一 `index.html`，原生 JavaScript（ES module），**沒有使用任何前端框架**
- 連線：Firebase Realtime Database（`asia-southeast1` 節點），負責房間狀態與號碼的即時同步
- 登入：Firebase 匿名驗證，玩家不需要註冊帳號
- 部署：GitHub Pages，推上去就自動更新

## 本機開發

不需要 npm、不需要安裝任何東西。clone 下來之後：

```bash
git clone https://github.com/hengda188188-png/company-events.git
cd company-events

# 起一個本機靜態伺服器，擇一即可
python -m http.server 8000        # Python 3
npx serve .                        # Node.js
```

然後開 <http://localhost:8000>。

> ⚠️ **不要直接雙擊 `index.html`。** 用 `file://` 開啟時，瀏覽器的來源不是合法網域，
> Firebase 匿名登入會失敗、整個房間功能都不能用。一定要走 `localhost`
> （`localhost` 預設就在 Firebase 的授權網域清單裡，不用另外設定）。

改完直接重新整理就看得到，改 `index.html` 就是改整個網站。
版本號在檔案裡的 `APP_VERSION`，改功能時順手更新，方便確認線上跑的是不是最新版。

### 想接手維護、或改用自己的 Firebase

`index.html` 開頭的 `firebaseConfig` 換成你自己的專案即可，然後在 Firebase 主控台完成三件事：

1. **Realtime Database** → 建立資料庫（地區建議 `asia-southeast1`）
2. **Authentication → Sign-in method** → 啟用「匿名」
3. **Authentication → 設定 → 已授權的網域** → 加入你的 GitHub Pages 網域

資料庫規則建議設成：

```json
{
  "rules": {
    "rooms": {
      ".read": "auth != null",
      ".write": "auth != null"
    }
  }
}
```

## 注意事項

`index.html` 裡面有 Firebase 的連線設定（`apiKey`、`databaseURL` 等）。
這是 **Firebase 前端設定，本來就設計成公開的**，不是密碼，Google 官方文件也是這樣寫的 ——
真正的防護來自 Firebase 主控台的 **Realtime Database 安全性規則**。

因此：**請確認資料庫規則沒有設成任何人都能讀寫**，否則不論程式碼放不放上 GitHub，
任何人都能直接對資料庫下手。規則設定在 Firebase 主控台 → Realtime Database → 規則。
